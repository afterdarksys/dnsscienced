## Critical Gaps (Blockers)

### GAP-1: RESOLVE-01/02/03 — Phase 11 features disabled in all production deployments

**Severity:** BLOCKER  
**Affected:** RESOLVE-01 (QNAME minimization), RESOLVE-02 (Aggressive NSEC), RESOLVE-03 (Serve Stale)

**Root cause:** `server.DefaultConfig()` in `internal/server/server.go:116` constructs `RecursiveConfig` as a partial struct literal with all three feature flags at their Go zero-value (`false`). `resolver.DefaultConfig()` — which sets all three to `true` — is never called in the server or config packages.

When a YAML config file is loaded (production deployment path), `config.Load()` YAML-decodes into the struct from `server.DefaultConfig()`. Since `config.example.yaml` and `config.production.yaml` both use `enable_qname_min: true` (a nonexistent field on `resolver.Config`; the correct key is `qname_minimization`), the YAML decoder silently ignores these entries. Result: all three features are `false` in every config-file deployment.

**Fix required:**
1. `server.DefaultConfig()` must embed `resolver.DefaultConfig()` as the initial `RecursiveConfig` value
2. `config.example.yaml` and `config.production.yaml` must replace `enable_qname_min:` with `qname_minimization:`, add `aggressive_nsec:`, `serve_stale:`, and `stale_ttl:` entries

### GAP-3: TestGetTTL test failure in internal/resolver

**Severity:** BLOCKER (clean test suite gate)  
**File:** `internal/resolver/recursive_test.go:289`

Phase 11 WR-01 changed `getTTL()` default return from `3600` to `300` (RFC 2308 §5 compliance). The existing test case `"no answers - default"` was not updated — still expects `3600`. `go test ./internal/resolver/...` fails with this test. Phase 11 SUMMARY claims all new tests pass and only the pre-existing `TestFindGlue` failure remains — `TestGetTTL` disproves this.

**Fix:** Update `recursive_test.go` line 289 expected value from `3600` to `300`.
