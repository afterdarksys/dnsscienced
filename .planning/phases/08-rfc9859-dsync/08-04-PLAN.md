BIND zone file format for TYPE66 (from RESEARCH.md §Zone File Serving):
```
; _dsync zone entries (RFC 3597 unknown-type presentation)
; 003B = CDS(59), 01 = NOTIFY, 0035 = port 53
; Target = example.com. in wire format: \x07example\x03com\x00
_dsync.example.com. 3600 IN TYPE66 \# 19 003B010035076578616D706C6503636F6D00
```

Hex breakdown for CDS→ns1.example.com. endpoint (manually computed):
  003B = 59 (CDS)
  01   = NOTIFY scheme
  0035 = 53 (port)
  036E733100 = "ns1" label (len=3, bytes n,s,1) 076578616D706C65 = "example" (7) 03636F6D = "com" (3) 00 = root
Full: 003B010035 036e73310076578616d706c6503636f6d00
Length: 5 + 4+1+7+1+3+1+1 = 5 + 18 = 23 bytes → \# 23 003B010035036e73310076578616d706c6503636f6d00

Use a simplified target "a.b." (wire: 01 61 01 62 00 = 5 bytes) for the test to keep the hex short:
  003B = CDS(59), 01 = NOTIFY, 0035 = 53, 016101620 0 = a.b.
  Total: 5 + 5 = 10 bytes → \# 10 003B010035016101620 0
  Full hex: 003b0100350161016200
  BIND: `_dsync.example.com. 3600 IN TYPE66 \# 10 003b0100350161016200`
