# Milestone v1.1: dnsfirewalld Completion

**Status:** ✅ SHIPPED 2026-04-23
**Phases:** 2–5 (continuing from v1.0 Phase 1)
**Total Plans:** 10

## Overview

Completed the remaining four dnsfirewalld subsystems to make the programmable DNS firewall production-ready end-to-end. Added gRPC management RPCs, an autonomous live threat feed poller, per-customer EDNS0 identity extraction, and multi-upstream redirect load balancing. Test suite grew from 19 to 44 passing tests.

### Phase 5: Redirect Load Balancing

**Goal**: Redirect verdicts (both static rules and Starlark) are distributed across a configured pool of upstream DNS targets using round-robin selection.
**Depends on**: Phase 3, Phase 4
**Plans**: 2 plans

Plans:
- [x] 05-01-PLAN.md — UpstreamPool + RedirectConfig + Firewall wiring (forwarder.go: UpstreamPool + Next(); config.go: RedirectConfig + Redirect field; firewalld.go: pool field + New() init + Check() pool-empty SERVFAIL)
- [x] 05-02-PLAN.md — Starlark builtin + policy relaxation + tests (starlark.go: pool field + updated redirect builtin; policy.go: compileRule relaxation; firewalld_test.go: 7 new integration tests covering REDIR-01 through REDIR-04)

**Details:**
- UpstreamPool uses atomic.Uint64 for lock-free round-robin: (counter.Add(1)-1) % len(upstreams)
- Empty pool at startup returns SERVFAIL — fail-fast before serving traffic
- redirect() Starlark builtin rejects server= kwarg (hard error) and calls pool.Next()
- compileRule relaxed: redirect rules no longer require redirect_server when pool is configured
- Per-rule redirect_server still supported and bypasses pool

## Milestone Summary

**Key Decisions:**
- gRPC admin registered conditionally via nil-guard: if fw := srv.GetFirewall(); fw != nil — safe when firewall.enabled is false
- FeedClient full-replace semantics: apply() replaces all previously ingested scores atomically
- edns0CustomerIDCode = 65000 (0xFDE8) — private-use range; do NOT use dns.EDNS0LOCALSTART (65001)
- UpstreamPool.Next() uses atomic.Uint64 for zero-lock round-robin distribution
- redirect() builtin rejects server= kwarg as hard error (D-02) — pool is the single source of truth

**Issues Resolved:**
- generate.sh *.proto glob generated stray management.pb.go in pb/ — deleted after codegen; upstream issue documented
- TotalNxdomain field name (lowercase d) — proto-generated naming; not TotalNXDomain
- Integration tests require ThreatIntel.BlockThreshold: 100 — default threshold 0 blocks all queries before Starlark stage

**Issues Deferred:**
- Authenticated feed endpoints (API key / Bearer token) — deferred to v2 FEED-05
- Multiple concurrent feed sources — deferred to v2 FEED-06
- Weighted upstream selection — deferred to v2 REDIR-05
- Health-check-based upstream removal — deferred to v2 REDIR-06
- Server-side CustomerID mapping table — deferred to v2 CUST-04

**Technical Debt Incurred:**
- HTTP admin handler stays in place as fallback; gRPC is additive overlay (intentional, per constraint)
- generate.sh regenerates management.proto as side-effect; stray files must be deleted manually after each codegen run
